## What this repo is

Course materials for **Prompt Engineering and Large Language Models**
(İstem Mühendisliği ve Büyük Dil Modelleri) — a university-wide elective at Ankara
Medipol University, Fall 2026–2027. Instructor: Mehmet Ali Akyol, PhD.

Currently mid-rebuild from the 2025–2026 delivery. The full design rationale lives in
[`docs/superpowers/specs/2026-08-07-course-rebuild-design.md`](docs/superpowers/specs/2026-08-07-course-rebuild-design.md).
**Read that spec before making content decisions.** This file covers mechanics only.

## Hard constraints — do not violate

These come from the approved course proposal.

- **No programming requirement.** Students are from medicine, law, education, business
  and engineering. Assume no Python, no command line, no API keys. No code in required
  material; any code shown is marked optional and explained in plain language.
- **Browser-based, free-tier, zero-install tools only.** Every activity needs a primary
  tool, an independent fallback, and an instructor-demo path.
- **Zero-prep activities.** Nothing a student must do beforehand; nothing the instructor
  must configure beyond opening a browser.
- **2+0 hours, 2 credits, 2 AKTS.** No AKTS increase is sought.
- **Lectures run 60–90 minutes**, not the full 2 hours. Cut content rather than compress
  delivery.
- **English** is the language of instruction. Forms are TR/EN.

## Decks

Decks are **generated by Python**, not hand-edited. Editing `week01.pptx` directly will
be overwritten on the next build — change `build_week01.py` instead.

- **Format:** `.pptx`, 16:9. Beamer is retired; `archive/` still holds the old `.tex`.
- **Theme:** all decks import `Theme/theme.py`. Never restyle a deck locally — change the
  theme so all 14 stay identical.
- **Speaker notes are mandatory and verbatim.** Not bullet reminders — the actual words
  to say. `theme.save()` refuses to write a deck with an unscripted slide; do not pass
  `require_notes=False` to get around it.
- **Size target:** 26–32 slides, ~180–220 script words per slide. 32 slides is a
  **ceiling**, not a target.
- Slide conventions: title slide with week number → overview slide ("Today: What We'll
  Explore") → `section_slide` per major topic → wrap-up → closing.

### Theme API (`Theme/theme.py`)

Text layouts: `new_deck()`, `title_slide()`, `section_slide()`, `content_slide()`,
`two_col_slide()`, `callout_slide()`, `activity_slide()`, `concepts_slide()`,
`closing_slide()`, `save()`.

Diagram layouts — **use these; don't let a week be all bullets**:

- `timeline_slide(title, [(marker, headline, detail), …])` — 4–6 events on a horizontal
  axis. Good for chronology and for revealing answers to a dating/ordering activity.
- `flow_slide(title, [(heading, detail), …], caption=…)` — 3–5 boxes with arrows. Good for
  pipelines, stages, before→after.
- `boxes_slide(title, [(heading, body), …])` — 2–4 side-by-side panels. Good for parallel
  concepts, failure modes, comparisons.

Rule of thumb: **at least two diagram slides per week.** A week of pure bullets is a
failure of preparation, not a style choice.

Bullet items accept `"text"`, `(1, "text")` for indent level, or a trailing `"bold"` /
`"plain"` style string. `"plain"` suppresses the bullet marker.

Palette constants (`INK`, `ACCENT`, `WARN`, …) are at the top of the file. The palette is
**not** official Ankara Medipol branding — if brand colours are published, change `INK`
and `ACCENT` and every deck picks them up on rebuild.

## Course structure

Weeks 1–5 baseline · Weeks 6–13 build · Week 14 synthesis. Build weeks 6–12 each produce
a named artifact that feeds the next week: **Micro-Tool → Grounded Assistant → Test Set →
Automation Chain → Field Build → Domain Pack → Attack & Patch Report**. Use these names
consistently across decks and exams.

Build weeks follow a fixed shape: demo (~10 min) → unpack (~30 min) → build (~20 min) →
`concepts_slide()` (~5 min).

## Assessment

Midterm 40% (in-class written) · Final 60% (written) · 5 pop quizzes as **+10 bonus
points**, all five counting. There is **no term project** — do not reintroduce one.

All papers are MCQ, LaTeX `article` class, built on the shared `Assessment/pelm.sty`.

- **Quizzes:** 10 questions, 4 options, 10 minutes. Each worth up to 10 bonus points.
- **Midterm:** 25 questions x 4 points = 100, 50 minutes, Weeks 1-7.
- **Final and makeup:** 25 questions x 4 points = 100, 60 minutes, whole course,
  weighted to Weeks 6-13 and split roughly 8 mechanism / 8 diagnosis / 9 design.

Every answer key carries an answer string for fast marking. **Verify it against the
per-question keys programmatically after any edit** — a mismatch is silent and
mis-marks the whole cohort.

Exams are conventional recall style by instructor decision. Because the course is
build-led, **every build week must close with a `concepts_slide()`** naming what is
examinable — that frame is the bridge between building and the exam bank.

## Content standards

- **Cite every factual and statistical claim.** Put sources on the slide. If a claim
  cannot be sourced, flag it rather than inventing one.
- **Verify currency by web search** — model names, capabilities, free-tier limits, tool
  availability. Do not rely on training data for anything version-dependent. Report which
  claims could not be verified.
- **Never build a learning outcome around one vendor.** Name tools in examples; teach the
  concept.
- **Rotate examples across disciplines** — healthcare, law, education, business,
  engineering. Not all software examples.
- Every week needs at least one in-class activity.

### Two standing rules set by the instructor

**No "what changed" narrative.** Do not compare the course or the field to last year or
to any earlier state. No "this used to be taught differently", no "the field has moved
on", no job-market-shift statistics. State what is true, present tense. Students should
never be told what they missed by not taking an earlier version.

**Slides must not depend on student participation.** Assume nobody runs the activity.
Every activity therefore needs its substance *on the slides* — at least one fully worked
example with concrete content the instructor can present and talk through alone. Never
write a slide whose content is only questions to the room ("who found X? hands up"), and
never write notes that require a student answer to continue. Participation should improve
the session, not be load-bearing. Put the "if the room is quiet, go straight to the worked
examples" instruction in the speaker notes.

### Known-stale content in `archive/`

Do not copy forward without checking: "Why Prompting Matters in 2025"; GPT-3/GPT-4
parameter counts; the "GPT-2 2019 / GPT-3 2020 / GPT-4 2023" timeline; Claude 3.x,
Gemini 1.5 and GPT-4o described as current; "knowledge cutoff e.g. 2023". **The old
Week 2 hallucination exercise uses "OpenAI released GPT-5 in 2018" as its false
statement — this no longer reads as false and must be replaced.**
